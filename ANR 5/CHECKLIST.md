Статус проверен по текущей реализации ANR 5. «Работает» означает, что функция реализована в приложении; ограничения учебного API перечислены отдельно.

## Часть 11 — React Hook Form и Zod

- [x] Формы используют `react-hook-form`.
- [x] Валидация пользователя и поста описана схемами Zod.

- [x] Форма поста общая для создания и редактирования.
- [x] Список тегов редактируется динамически через `useFieldArray`.
- [x] Ответ с ошибкой сервера можно отобразить у соответствующего поля через `setError`.

## Часть 12 — TanStack Query

- [x] Список постов загружается через `useQuery`.
- [x] Для загрузки и ошибки запроса есть отдельные состояния и кнопка повтора.
- [x] Детали поста загружаются отдельным запросом; для отсутствующего поста показывается ошибка.
- [x] Результаты списков и деталей хранятся в кэше TanStack Query.
- [x] Создание, редактирование и удаление выполняются через `useMutation`.
- [x] После мутаций связанные запросы инвалидируются.
- [x] Удаление и создание оптимистично обновляют список; при ошибке список восстанавливается.

## Дополнительное задание — каталог постов

- [x] Есть страницы списка, создания, просмотра и редактирования поста.
- [x] Список поддерживает поиск по заголовку и пагинацию.
- [x] Поиск и номер страницы сохраняются в параметрах URL (`search`, `page`).
- [x] При наведении или фокусе на ссылку пост заранее кладётся в кэш деталей.
- [x] Форма проверяет заголовок, текст, автора, теги, статус и дату публикации.
- [x] Есть сообщения о загрузке, обновлении, ошибке и пустом результате поиска.

## Что не работает или ограничено

- [ ] Созданные и отредактированные посты не сохраняются на сервере после перезагрузки.
- [ ] Удалённые посты могут вернуться после повторной загрузки.
- [ ] Реальная серверная ошибка валидации не проверяется: JSONPlaceholder её не возвращает, поэтому показ ошибки поля демонстрируется обработчиком формы.

Это ограничения JSONPlaceholder: он принимает учебные POST/PUT/DELETE-запросы, но не сохраняет изменения. Для постоянного хранения нужен API с базой данных.
